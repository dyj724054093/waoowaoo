# waoowaoo 吸收 moyin 能力的风险优先开发计划

## 1. 目标

本计划的目标不是把 `moyin-creator` 的形态搬进 `waoowaoo`，而是把其已验证有效的治理能力迁移到 `waoowaoo`，同时保持 `waoowaoo` 现有生产主链稳定。

本计划遵循以下硬约束：

- P0 / P1 不做 Persona 化。
- 优先建设阶段边界与治理闭环。
- 先控错，再提质，最后再考虑结构升级。
- 所有新增能力必须可观测、可回滚、可验证。

## 2. 已锁定结论

### 2.1 角色抉择

- P0、P1 不引入 Persona。
- P2 才允许最小角色集试点，且最多 2~3 个。
- `Orchestrator` 保持系统职责，不人格化。

### 2.2 当前真正值得吸收的能力

优先吸收的是：

- feature router 思路
- model limits 学习
- 并发错峰
- shot calibration
- viewpoint analysis
- `needsEndFrame`
- 三层 prompt 契约

而不是照搬：

- 多 Persona 形态
- 多节点协作叙事
- 接口组织外观

## 3. 开发规划原则

本次开发按风险优先推进，而不是按“功能炫酷程度”推进。

优先级判断规则如下：

1. 先减少坏结果进入系统的概率。
2. 再减少坏结果扩散的成本。
3. 再提升输出质量上限。
4. 最后才评估是否需要结构升级。

因此开发顺序必须是：

**治理底座 → 最小质量闭环 → 增强插件 → 结构升级评估**

## 4. 分阶段开发计划

### P0：治理闭环落地

目标：在不重构主链的前提下，让链路先可控。

#### P0-1 Gates / 硬拦层

建立致命错误拦截机制，至少覆盖：

- JSON 不可解析
- 必填字段缺失
- 模型限制 / 成本超限
- 输出结构严重偏离 schema

要求：

- 拦截原因可记录
- 拦截结果可观测
- 不允许坏数据继续流入后续 worker / DB

#### P0-2 Router 策略化

统一以下能力：

- feature 路由
- model/provider 选择规则
- model limits 学习
- 队列优先级策略

要求：

- 路由逻辑集中
- 禁止散落在多个 handler 中各自判断

#### P0-3 Metrics

先补齐分阶段指标：

- 成功率
- 拦截率
- 重试率
- 修复率
- 成本
- 延迟
- 失败分布

要求：

- 指标必须能支撑后续是否引入 calibration / viewpoint / Persona 的判断

### P1：最小质量闭环

目标：在单节点试点质量增强，而不是全链铺开。

#### P1-1 `needsEndFrame`

先规则化，不交给模型自由发挥。

最低要求：

- 有位移 / 状态变化 / 镜头运动时触发
- 不确定时宁可 true
- 接入回退与重试策略

#### P1-2 三层 Prompt 契约试点

只在一个高价值节点启用：

- `imagePrompt`
- `videoPrompt`
- `endFramePrompt`

要求：

- 必须真实接入链路
- 必须验证是否降低修复率 / 返工率
- 禁止只停留在 schema 层

#### P1-3 Calibration 接入

把校准做成阶段插件，不做角色系统。

要求：

- 先定义阶段位置
- 先定义合格阈值
- 先定义失败回传机制

### P2：增强与升级评估

目标：在指标支持前提下再做增强，而不是先概念化扩张。

#### P2-1 Viewpoint Analysis

定位为：

- 校验插件
- 建议层
- 非主决策人格

#### P2-2 并发错峰

引入 `runStaggered` 式并发控制，但前提是：

- 已有队列延迟数据
- 已有重试成本数据
- 已有失败分布数据

#### P2-3 是否引入最小角色集

只有在以下条件满足后才讨论：

- 阶段 IO 契约稳定
- Gates / Router / Metrics 成熟
- 单执行体复杂度已经成为瓶颈
- 校准链收益已被证明

届时才允许讨论：

- Gatekeeper
- Calibrator
- Viewpoint Analyst

## 5. 推荐的开发拆包

### 包 1：治理底座包

- Gates
- Router
- Metrics
- limit 学习入口

### 包 2：EndFrame 包

- `needsEndFrame`
- schema
- 回退策略
- 指标

### 包 3：Prompt 契约试点包

- 三层契约
- 单节点接入
- 对比实验

### 包 4：Calibration 包

- 阶段接入
- 阈值
- 回传机制

### 包 5：增强插件包

- viewpoint analysis
- 并发错峰
- 角色预留位

## 6. 风险说明

### 最大风险

如果跳过治理底座，直接上质量增强，会出现：

- 成本上升
- 失败扩散
- 排障更难
- 规则散落
- 后续必须返工收敛

### 明确禁止

- P0/P1 直接做多 Persona
- 没有指标先做复杂校准链
- 在多个节点同时铺三层 prompt 契约
- Router / Gates 逻辑分散在多个 handler 私自实现

## 7. 最终建议

本次开发应采用：

**风险优先、阶段边界优先、治理闭环优先**

执行顺序必须是：

**先治理，后提质，再增强，最后评估结构升级。**
