## 1. TypeScript 构建错误修复

项目因 Seedance 集成等大量改动后，src 目录累积 212 个 TypeScript 编译错误，导致 `next build` 无法通过。本次对所有影响构建的类型错误进行了定位和修复，最终 src 目录编译零错误，`next build` 构建成功。

**功能点**
- 生成 Prisma Client，解决 `Prisma.JsonNull`、`Prisma.Decimal`、`PrismaClientKnownRequestError` 等类型缺失（约 150 个错误）
- 补全 `prompt-i18n/catalog.ts` 中缺失的 3 个 Seedance prompt ID（`np_seedance_storyboard_plan`、`np_seedance_cinematographer`、`np_seedance_storyboard_detail`）
- 在 `ProjectSnapshotInput` 接口中补充 `workflowMode` 字段
- 修复 `script-to-storyboard-helpers.ts` 中 Prisma Json 字段的类型兼容问题（`characterLabels` 使用 `Prisma.JsonNull` + `Prisma.InputJsonValue` 断言）

**修改文件**

| 文件 | 变更 |
|------|------|
| `src/lib/prompt-i18n/catalog.ts` | 将 3 个 Seedance prompt 条目从运行时注入改为对象字面量内声明，消除 `Record<PromptId, ...>` 类型不完整错误 |
| `src/app/[locale]/.../workspace-controller-view-model.ts` | `ProjectSnapshotInput` 接口新增 `workflowMode: string | undefined` 字段 |
| `src/lib/workers/handlers/script-to-storyboard-helpers.ts` | 新增 `Prisma` import；`characterLabels` 空值改用 `Prisma.JsonNull`，数组值添加 `as Prisma.InputJsonValue` 类型断言 |

**关键决策**：catalog.ts 原方案是运行时注入 seedance 条目以避免修改对象字面量，但 TypeScript 在字面量阶段就检查 `Record<PromptId, ...>` 的完整性，运行时注入绕不过编译检查。直接内联是最简洁的修法。

**遗留问题**：无

## 2. tests 目录类型错误修复

修复 tests 目录下全部 74 个 TypeScript 类型错误，涉及 17 个测试文件。修复后全项目（src + tests）TypeScript 编译零错误。

**功能点**
- 修复 Next.js 15 路由处理函数签名变更导致的 21 个 TS2554 错误（路由 handler 需要第二参数）
- 修复 25 个 TS2493 错误：`vi.fn()` mock 的 `.mock.calls[N]` 访问空 tuple，统一添加 `as unknown[]` 类型断言
- 修复 8 个 TS2322 错误：mock 返回值 `vi.fn(async () => [])` 推断为 `never[]`，改为显式标注 `[] as Record<string, unknown>[]`
- 修复 5 个 TS2722 错误：`callbacks.onStage` 等可能为 undefined，添加非空断言
- 修复 5 个 TS2352 错误：`null as EffectCleanup` 等不安全转换，改用 `as unknown as` 双重断言
- 修复 5 个 TS2345 + 2 个 TS2558 + 2 个其他错误

**修改文件**

| 文件 | 变更 |
|------|------|
| `tests/integration/api/contract/task-infra-routes.test.ts` | 路由调用补第二参数；mock 返回值类型标注；`addChannelListenerMock` 实现类型断言；`RouteContext` 类型修正 |

| `tests/unit/worker/reference-to-character.test.ts` | `readGenerateCall` 中 mock.calls 访问添加类型断言 |
